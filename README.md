# ResumeGenerator v1

Fully automated job application pipeline. Discovers jobs, scores them, generates tailored resumes and cover letters, and tracks everything in a single spreadsheet.

---

## How it works

```
discovery/auto/pipeline.py   (cron: every 3h)
  ↓  scrapes LinkedIn/Indeed via 9 keyword queries
  ↓  pre-filters obvious non-PM roles (no API call)
  ↓  scores with Claude Haiku, writes to jobs.xlsx

discovery/auto/score_screenshots.py   (manual, as needed)
  ↓  LinkedIn screenshot PDFs → vision extract → JobSpy JD fetch → score
  ↓  catches top-tier jobs that bypass automated keyword queries
  ↓  appends to jobs.xlsx with source=screenshot

jobs.py pipeline              (cron: every 12h)
  ↓  promotes top-scored jobs → creates apps/<Company>/ dirs
  ↓  runs run_app.py for each → resume + CL outputs
  ↓  writes folder_path + status=generated back to jobs.xlsx

You                           (every ~12h)
  ↓  open apps/<Company>/ dirs, review resume + CL, decide to apply
  ↓  python jobs.py mark --id 42 --status applied
```

---

## Status lifecycle

```
new → queued → promoted → generated → applied
               (auto)     (auto)      (manual)

Terminal (automation never touches): applied, rejected, skip, skipped
```

## Running manually

### Discovery — pipeline

```bash
# Standard run (scrape last 24h, score, write xlsx)
python discovery/auto/pipeline.py

# Widen scrape window (e.g. after a gap)
python discovery/auto/pipeline.py --hours-old 48

# Re-score any unscored rows already in xlsx (status=new, no fit_score)
python discovery/auto/pipeline.py --skip-scrape

# Dry run — scrape and score but don't write
python discovery/auto/pipeline.py --dry-run

# Override results per query (default: 100 for 24h runs)
python discovery/auto/pipeline.py --results 200

# Use a different model (default: claude-haiku-4-5-20251001)
python discovery/auto/pipeline.py --model claude-sonnet-4-6

# Suppress per-job output
python discovery/auto/pipeline.py --quiet
```

### Discovery — screenshot scoring

```bash
# Score PDFs in discovery/manual/ (default)
python discovery/auto/score_screenshots.py

# Different directory
python discovery/auto/score_screenshots.py --dir path/to/screenshots

# Dry run — don't write to xlsx
python discovery/auto/score_screenshots.py --dry-run

# Widen JD search window (default: 168h = 7 days)
python discovery/auto/score_screenshots.py --hours-old 336

# Skip JobSpy JD fetch — score on title+company only (fast, lower confidence)
python discovery/auto/score_screenshots.py --no-jd-fetch
```

### JD fetch / retry (for missing JDs in xlsx)

```bash
# Retry all screenshot rows with no JD
python discovery/auto/jd_fetch.py

# Specific row IDs
python discovery/auto/jd_fetch.py --id 1540,1541,1543

# After manually pasting JDs
python discovery/auto/jd_fetch.py --rescore-pastes
```

⚠️  **Run score_screenshots.py and jd_fetch.py from your Mac terminal, not the Cowork VM.**
The Cowork VM routes traffic through an ephemeral MITM proxy (Coworkd MITM CA) that presents a
self-signed certificate, causing `CERTIFICATE_VERIFY_FAILED` errors.

> **jobs.py workaround (2026-03-21):** `jobs.py` now auto-detects the VM environment
> (`/sessions` exists + `HTTPS_PROXY` set) and patches the `anthropic` httpx transport to
> skip SSL verification, so the application pipeline *can* run unattended from the Cowork
> scheduled task.  `score_screenshots.py` does **not** have this patch and still requires the
> Mac terminal.

### Application pipeline

```bash
# See what's queued (top 20 by fit score)
python jobs.py list --status queued --top 20

# See promoted (generated, waiting to apply)
python jobs.py list --status generated

# Promote specific jobs and generate immediately
python jobs.py promote --id 42,47
python jobs.py generate --all-promoted

# Batch-generate for every apps/ dir that has a jd.txt (skips already-generated)
# Dirs without an xlsx row get a new row auto-created (id, company, folder_path,
# status=generated, jd_text, role_title from strategy.json if available)
python jobs.py generate --all-apps
python jobs.py generate --all-apps --force        # rerun even if resume already exists
python jobs.py generate --all-apps --parallel 3   # 3 jobs at once
python jobs.py generate --companies Flexera,Lennox,Risepoint --parallel 3
python jobs.py generate --companies Flexera,Lennox --resume-only --parallel 2
python jobs.py generate --companies Flexera,Lennox --no-docx   # skip docx for debug/test runs

# Auto resume-only: if a dir has cl_*.txt but no resume_*.txt (run was interrupted),
# --resume-only --no-strategy is applied automatically per-dir. Or force it for all:
python jobs.py generate --all-apps --resume-only

# Timeout: default 2400s (40 min). Raise for slow API runs:
python jobs.py generate --all-apps --timeout 3600

# Generate for a single company (will recreate app dir from xlsx if dir is missing)
python jobs.py generate --company Stripe

# Generate for a hand-picked list of companies
python jobs.py generate --companies Stripe,Flexera,Lennox --parallel 3
python jobs.py generate --companies Stripe,Flexera --resume-only --parallel 2

# Full pipeline in one shot (same as what the cron does)
python jobs.py pipeline --min-score 8.0 --top 10

# Run a single application manually
python run_app.py Stripe
python run_app.py Stripe --resume-only
python run_app.py Stripe --cl-only
python run_app.py Stripe                     # also produces .docx by default
python run_app.py Stripe --no-docx          # skip .docx for debug/test runs
python run_app.py Stripe --no-strategy       # skip strategy step
python run_app.py Stripe --no-rewrite --no-score --no-qc  # fast mode ~$0.08
python run_app.py Stripe --score-only        # re-score existing resume txt, rename docx
python run_app.py Stripe --docx-only         # regenerate docx from latest resume_*.txt with no AI

# Non-PM resume track (Strategy / Consulting / S&O / PgM / RevOps)
python run_app.py McKinsey --track nonpm     # uses freeform_master_nonpm.txt
python run_app.py McKinsey --track nonpm --resume-only

# Mark a job after applying
python jobs.py mark --id 42 --status applied

# Skip a role you don't want to apply to
python jobs.py mark --id 55 --status skip

# Re-sort and re-apply full xlsx formatting without changing any data
python jobs.py sort

# Scan apps/ dirs and backfill folder_path in xlsx
python jobs.py sync

# Monthly cleanup
python jobs.py archive --older-than 60
```

## jobs.xlsx protection

Every `save_jobs()` call automatically creates `jobs.xlsx.bak` before writing. If another agent or process corrupts the file's formatting or view, restore with:

```bash
cp "discovery/jobs.xlsx.bak" "discovery/jobs.xlsx"
```

The `.bak` file reflects the state immediately before the most recent programmatic write. For additional protection against accidental edits, you can use Excel's **Review → Protect Workbook** feature after a clean write — though this also blocks the cron from writing until you unprotect it.

## Source taxonomy

The `source` column in jobs.xlsx distinguishes how each job entered the tracker:

| source       | meaning                                                              |
|--------------|----------------------------------------------------------------------|
| `linkedin`   | Found by automated pipeline scraper (LinkedIn)                       |
| `indeed`     | Found by automated pipeline scraper (Indeed)                         |
| `screenshot` | Extracted from LinkedIn screenshot PDF via score_screenshots.py      |
| `seeded`     | Pre-seeded historical jobs (applied before this system was built)    |
| `manual`     | Manually added rows (direct input into xlsx)                         |

Deduplication runs automatically between pipeline and screenshot sources. There is no cross-dedup between `seeded` and live sources (no risk — seeded jobs have already been applied to).

## Blocklist

`discovery/blocklist.txt` — one company name per line. Supports `fnmatch` wildcards (case-insensitive).

```
TikTok
Nvidia
IBM
# *staffing*       ← commented lines are ignored
# tik*             ← wildcards supported
```

Blocklisted companies are:
- **Skipped at promotion time** — `jobs.py promote` and `jobs.py pipeline` filter them out before applying `--top N`, so you always get N real candidates
- **Visually flagged in xlsx** — rows appear greyed out with strikethrough at the bottom of their status group
- **Not deleted from xlsx** — they stay in the tracker so dedup still works

To add a company mid-session: edit `discovery/blocklist.txt` directly, then run `python jobs.py sort` to refresh the xlsx view.

## Scorer pre-filters (no API call)

Three pre-filters run before any Claude API call, saving tokens on obvious rejects:

1. **Role-type mismatch** — checks `role_title` for non-PM domains: pharmacy/medical, architecture/construction, trades, non-PM engineering disciplines (electrical, mechanical, firmware, etc.), accounting, legal, logistics/warehouse, HR. Only fires on unambiguous titles — grey areas like "Supply Chain PM" pass through.

2. **Immigration hard reject** — checks JD text for US-citizen-only, security clearance required, explicit CPT/OPT rejection. "No visa sponsorship" alone is NOT a hard reject (usually means no future H-1B, doesn't affect CPT/OPT internships).

3. **Full-time hire level mismatch** — rejects if no internship signal in title/JD and 4+ years experience is explicitly required.

## Rate limiting notes

Scoring runs at 2 parallel workers to stay under the 50K tokens/minute org limit (~1,800 tokens/job). On rate-limit hits (429), the scorer backs off exponentially: 60s → 120s → 240s → 480s, then retries (up to 5 attempts).

Do not run multiple pipeline instances simultaneously.
