# NonPM Proof Gaps — Next Story-Bank Expansion

Goal: move strong nonPM resumes from the high-7s / low-8s into the `8.5+ SEND`
zone by adding proof types that the current company-story spine cannot express
cleanly enough for certain role families.

This is not a prompt-polish problem anymore. The current route system and
variant bank can now produce better nonPM bullets, but the generator still lacks
some source-proof types in the main experience section.

## 1. Commercial / GTM — Missing Proof Types

These roles still top out early when the JD explicitly asks for pipeline,
revenue intelligence, or messaging optimization.

### Missing proof type A — Revenue-intelligence artifact
What the resume needs to show:
- pulled patterns from customer / funnel / deal data
- converted them into a GTM recommendation or commercial decision
- named the artifact or output, not just the diagnosis

Ideal bullet shape:
- `analyzed X cohort / funnel / loss pattern`
- `built Y segmentation / recommendation / prioritization model`
- `changed Z GTM motion / offer / targeting decision`

Closest current stories:
- `G2` pricing
- `G3` funnel leak
- `I1` renewal-risk / billing integrity
- `I3` remediation brief

Current gap:
- no bullet directly resembles CRM / call-data / win-loss synthesis
- scorer keeps calling this out for roles like Nuvo

### Missing proof type B — ICP / account-targeting decision
What the resume needs to show:
- identified which buyer / segment / market to prioritize
- showed why that segment was better
- translated that into a targeting or sequencing decision

Ideal bullet shape:
- `identified the segment / market with shortest time-to-value`
- `built a prioritization logic`
- `informed targeting / sequencing / expansion`

Closest current stories:
- `G2`
- `O1`
- founder advisory proof

Current gap:
- we have segmentation and opportunity-sizing
- we do not yet have enough explicit account-targeting or GTM sequencing language

### Missing proof type C — Messaging / buyer-objection proof
What the resume needs to show:
- surfaced the real buyer objection
- turned it into a clearer message, proof surface, or commercial motion

Ideal bullet shape:
- `found the objection that stalled evaluation`
- `changed the proof / message / surface buyers needed`
- `improved close / adoption / conversion`

Closest current stories:
- `H1`
- `H2`

Current gap:
- Hevo stories are close, but still often read product / reliability-first
- we need sharper GTM-language variants that sound like buyer-signoff logic

## 2. AI-Automation — Missing Proof Types

These roles still under-score when the JD asks for hands-on workflow redesign,
tool evaluation, or executive recommendation delivery.

### Missing proof type D — Workflow evaluation artifact
What the resume needs to show:
- mapped a workflow or handoff
- evaluated where AI / automation should intervene
- named the decision rule or evaluation lens

Ideal bullet shape:
- `mapped workflow friction / failure states`
- `defined evaluation criteria or decision rules`
- `prioritized automation opportunities`

Closest current stories:
- `H2`
- `O2`
- `P-LOREAL`

Current gap:
- `P-LOREAL` carries this best today, but lives in Section 3B
- the main section still lacks enough workflow-evaluation proof

### Missing proof type E — Executive recommendation delivery
What the resume needs to show:
- translated ambiguous findings into a recommendation for leadership
- named the recommendation artifact or output
- ideally attached a concrete downstream action

Ideal bullet shape:
- `translated findings into recommendation / brief / framework`
- `aligned stakeholders / leadership`
- `moved to pilot / implementation / priority change`

Closest current stories:
- `I3`
- `H1`
- `P-LOREAL`

Current gap:
- `I3` is closer now, but still often ends with coordination rather than a
  crisp business or implementation outcome
- Momentum-style roles need at least one main-section bullet that feels like
  recommendation delivery, not just technical diagnosis

### Missing proof type F — Adoption / rollout decision proof
What the resume needs to show:
- considered constraints of trust, adoption, or operator behavior
- designed the automation or AI workflow accordingly

Ideal bullet shape:
- `identified why operators / buyers would not trust the system`
- `redesigned workflow or proof surface around that constraint`
- `improved adoption / pilot viability / decision speed`

Closest current stories:
- `H1`
- `H2`
- `O2`

Current gap:
- the stories are close, but the variants need one more layer of
  workflow-adoption framing

## 3. What To Add Next

### A. New anchor variants from existing stories
Highest-priority additions:
- `H1` GTM-signoff variants
- `H2` operator / evaluation-surface variants
- `I3` recommendation-delivery variants with sharper downstream outcomes
- `O2` workflow-adoption variants

### B. New explicit story units if source detail exists
Commercial / GTM:
- CRM or call-data synthesis
- segment-targeting / account-prioritization logic
- messaging iteration against buyer objections

AI-Automation:
- workflow mapping + tool evaluation
- executive recommendation framework
- adoption / trust / rollout decision design

## 4. Validation Questions For The Next Pass

For commercial-GTM resumes:
- Does the main section show revenue-intelligence or only diagnosis?
- Does at least one bullet sound like targeting / sequencing / messaging proof?

For AI-automation resumes:
- Does the main section show workflow evaluation and recommendation delivery?
- Is there at least one bullet that sounds like operator / stakeholder adoption
  logic rather than just system reliability?

If the answer is still "no", the next move is story-bank expansion, not another
general rewrite pass.
