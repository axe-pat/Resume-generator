# Profile Maxing Lab

> **COUNTERFACTUAL REFERENCE MATERIAL - NOT FOR APPLICATION, INTERVIEW, OR OUTREACH USE**
>
> This folder deliberately contains invented ownership, mechanisms, decisions, titles, and outcomes. It is a design target for what an exceptional product profile *could* look like if the underlying work were actually done and verified. It is not part of the factual Story Engine.

## Why this exists

The factual profile already has strong technical depth, but job titles and several stories under-signal product ownership. This lab answers a narrower question: if the same companies, dates, and domains formed the boundary, what would a genuinely maxed-out technical product manager / product engineer story system look like?

The answer is a coherent progression:

1. **Optum:** make regulated systems safe and useful.
2. **Intuit:** turn invisible integrity failures into customer and revenue decisions.
3. **Hevo Data:** translate infrastructure architecture into enterprise trust and strategy.
4. **Gojek:** treat technical constraints as marketplace, growth, and pricing levers.
5. **FlairX:** own AI-product workflows, enterprise adoption, and commercial execution formally.
6. **USC / independent builds:** prove current product judgment through consulting and an operated AI product.

## Isolation contract

- Nothing in this folder may be copied into `profile/profile.md`, resume prompts, cover-letter prompts, the factual story bank, or Outreach automatically.
- Every new story begins with a counterfactual warning and ends with a provenance ledger.
- The ledger separates:
  - **A - anchored:** supported by a local source;
  - **R - reframed:** a stronger interpretation of an anchored fact;
  - **X - invented:** counterfactual detail created for this exercise;
  - **V - verification/build target:** evidence or work required before a claim can become externally usable.
- The reference resume repeats the warning in the document header and footer. There is intentionally no unlabeled copy.
- A claim graduates from `X` to the factual engine only after source evidence, personal confirmation, and a defensible ownership boundary exist.

## What is here

- `PROFILE_MAXING_INDEX.md` - the complete portfolio, competency map, and recommended story stack.
- `stories/` - twelve new counterfactual reference stories that complete the existing seven gold references.
- `resume/maxed_profile_reference_resume.md` - plain-text source for the reference resume.
- `resume/maxed_profile_reference_resume.docx` - rendered, one-page reference artifact with persistent warnings.
- `scripts/build_reference_resume.py` - deterministic DOCX builder used only for the labeled reference artifact.
- `rendered_resume/` - internal render-QA output; not a user deliverable.

## How to use it safely

Use this material in three ways:

1. **Profile diagnosis:** compare each counterfactual claim with the current factual story and name the missing product behavior.
2. **Work selection:** choose live projects that create the missing evidence - discovery logs, experiment readouts, adoption metrics, roadmap decisions, stakeholder artifacts, or launch outcomes.
3. **Truth conversion:** after the work exists, write a separate defensible story from the evidence. Do not simply delete the warning from the counterfactual version.

The highest-value gap is usually not a more impressive sentence. It is the missing loop behind the sentence: customer evidence -> explicit product decision -> shipped mechanism -> measured result -> clear personal ownership.
