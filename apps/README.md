# Apps Directory

One subdirectory per job application. The pipeline creates these automatically via `jobs.py promote`. You can also create them manually for jobs not in jobs.xlsx.

---

## Directory layout

```
apps/
└── <Company>/
    ├── jd.txt                  Job description text (written by jobs.py promote, or paste manually)
    ├── intel.txt               Optional: insider context, referral notes, things to emphasize
    │                           (written manually — injected into strategy generation)
    ├── strategy.json           Positioning brief (generated by run_app.py, overwritten each run)
    ├── resume_YYYY-MM-DD.txt   Paste-ready experience + skills sections
    ├── resume_YYYY-MM-DD.docx  Formatted .docx resume (generated by default; use --no-docx to skip)
    ├── cl_YYYY-MM-DD.txt       Paste-ready cover letter
    └── cl_YYYY-MM-DD.json      CL audit trail (step analysis + QC data)
```

---

## Creating an app directory

### Via jobs.py (for jobs already in jobs.xlsx)

```bash
# Promote a job by ID — creates apps/<Company>/ and writes jd.txt
python jobs.py promote --id 42

# Then generate the resume + CL
python jobs.py generate --all-promoted

# Or promote + generate in one step via pipeline
python jobs.py pipeline --min-score 8.0 --top 10
```

### Manually (for jobs not in jobs.xlsx)

```bash
mkdir apps/Stripe

# Paste the full JD into jd.txt
# (optional) Paste any insider context into intel.txt

python run_app.py Stripe
```

If you batch-run manual app dirs through `jobs.py generate --all-apps`, any dir that has no linked `jobs.xlsx` row now reuses the shared discovery pre-filters first (role-type mismatch, immigration hard reject, obvious full-time level mismatch). This is a no-AI guardrail for manually pasted JDs only; promoted/discovered jobs already passed discovery filtering upstream.

## Regenerating outputs

You can always re-run `run_app.py` for an existing directory. It reads `jd.txt` and `intel.txt`, overwrites `strategy.json`, and appends a new dated resume + CL (old files are kept).

```bash
python run_app.py Stripe                # full pipeline (PM track by default, includes docx)
python run_app.py Stripe --resume-only  # resume only
python run_app.py Stripe --cl-only      # CL only
python run_app.py Stripe --no-strategy  # skip strategy step (reuses existing strategy.json)
python run_app.py Stripe --no-rewrite   # skip resume voice rewrite pass
python run_app.py Stripe --no-qc        # skip CL quality check
python run_app.py Stripe --no-docx      # skip formatted .docx for debug/test runs
python run_app.py Stripe --no-rewrite --no-score --no-qc  # fast mode (~$0.08)
python run_app.py Stripe --docx-only    # regenerate .docx from latest resume_*.txt with no AI

# Multi-company batch generation via jobs.py
python jobs.py generate --companies Stripe,Flexera,Lennox --parallel 3
python jobs.py generate --companies Stripe,Flexera --resume-only --parallel 2
python jobs.py generate --companies Stripe,Flexera --no-docx

# Non-PM resume track (Strategy / Consulting / S&O / PgM / RevOps / Ops)
python run_app.py McKinsey --track nonpm             # explicit nonpm track
python run_app.py McKinsey --track nonpm --resume-only
# Note: if --track is omitted, the runner auto-detects nonpm from role_family in strategy.json
```

**Parallelization:** when both resume and CL are enabled (the default), `run_app.py` runs them in parallel after the shared strategy step, saving ~1–1.5 min per application. Output is buffered per-thread and printed sequentially (resume first, then CL) so the terminal is never garbled.

**Auto-logging:** every `run_app.py` run writes a plain-text log to `logs/run_app_<Company>_YYYYMMDD_HHMMSS.txt` at the project root. ANSI colour codes are stripped so logs are readable without a terminal. The path is printed at the end of each run. Resume, CL, and shared strategy API calls now also log their elapsed time, which makes slow-run diagnosis much easier.

## After applying

```bash
# Mark as applied (manual step — never automated)
python jobs.py mark --id 42 --status applied

# Skip a role you've decided not to apply to
python jobs.py mark --id 55 --status skip
```

Terminal statuses (`applied`, `rejected`, `skip`) are never touched by automation.
